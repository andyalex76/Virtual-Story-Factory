# Virtual Story Factory 2.3

Интеллектуальная оркестратор-воркер платформа для автоматизированного и полуавтоматизированного создания литературных произведений (книг, романов, повестей и сценариев).

---

## 1. О проекте (Overview)

**Virtual Story Factory** — это производственная фабрика историй с мультиагентной системой, построенная по принципу взаимодействия автономных ролевых агентов: **Редактора**, **Писателя**, **Критика** и **Дизайнера** под управлением пользователя-режиссера.

Платформа решает ключевые проблемы генерации длинных текстов в нейросетях:
* Потерю контекста и забывание фактов о персонажах/мире.
* Накопление стилистических и сюжетных ошибок.
* Раздувание расхода токенов при росте объема книги.
* Отсутствие контроля версий и невозможность отката к предыдущим итерациям.

---

## 2. Мультиагентная архитектура (Multi-Agent System)

Каждый агент наделен специализированным системным промптом (System Persona), своей ролью в конвейере и оптимально подобранной моделью искусственного интеллекта:

| Роль агента | Отображение / Иконка | Используемая модель | Зона ответственности |
|---|---|---|---|
| **Главный Редактор** (`editor`) | Синий / 🤖 Bot | `gemini-3-flash-preview` | Оркестрация процесса, создание концепции и Story Bible, утверждение структуры, компиляция книги. |
| **Писатель** (`writer`) | Изумрудный / ✒️ PenTool | `gemini-3-pro-preview` | Написание художественного текста глав на основе Story Bible и нарративного моста предыдущих глав. |
| **Литературный Критик** (`reader`) | Оранжевый / 🔍 Search | `gemini-3-flash-preview` | Глубокий аудит текста черновика, оценка стиля и логики (1-10), проверка исправлений (re-review). |
| **Креативный Дизайнер** (`designer`) | Фиолетовый / 🎨 Palette | `gemini-3-flash-preview` | Разработка маркетинговых материалов, аннотаций (blurbs), промптов для обложки и постов для соцсетей. |
| **Пользователь** (`user`) | Сине-серый / 👤 User | — | Режиссер проекта: направляет агентов, правит промпты, утверждает или отправляет на доработку. |

## 3. Этапы производственного конвейера (Pipeline Stages)

Конвейер строго детерминирован перечислением переходов `Stage`:

```
   ┌─────────┐
   │  INIT   │ ── Режим: «С нуля» или «Импорт/Продолжение»
   └────┬────┘
        ▼
   ┌─────────┐
   │  BRIEF  │ ── Создание и утверждение Story Bible (Сеттинг, Персонажи, План глав)
   └────┬────┘
        ▼
   ┌─────────┐
   │ WRITING │ ── Писатель создает черновик главы (Chapter_X_Draft.md)
   └────┬────┘
        ▼
   ┌──────────┐
   │ CRITIQUE │ ── Критик анализирует главу (1-10)
   └────┬─────┘
        │
        ├──► [Принять правки] ──► Повторная доработка Писателем
        │
        └──► [Утвердить и дальше] ──► Сохранение Chapter_X_Final.md
                 │                     и переход к следующей главе
                 ▼ (после всех глав)
           ┌─────────┐
           │ RELEASE │ ── Компиляция {BOOK_NAME}.md и создание промо-материалов
           └─────────┘
```

1. **INIT (Инициализация):**
   * *Режим 1 (Создание с нуля):* Редактор предлагает 3 варианта жанров/сеттингов и переходит к формированию Story Bible.
   * *Режим 2 (Продолжение книги):* Пользователь загружает файлы `Final_Story_Bible.md` и готовые главы `Chapter_X_Final.md`. Система моментально определяет номер следующей главы и передает задачу Писателю.
2. **BRIEF (Формирование Story Bible):**
   * Редактор генерирует единый структурированный документ `# STORY BIBLE`, содержащий: Название (`TITLE`), Логлайн (`LOGLINE`), Описание мира (`SETTING`), Досье персонажей (`CHARACTER BIOGRAPHIES` с полями Role, Description, Backstory, Motivation) и План глав (`CHAPTER PLAN`).
   * Кнопка «Утвердить Story Bible» фиксирует документ в Памяти проекта и переводит систему в режим написания.
3. **WRITING (Написание глав):**
   * Запуск генерации черновика Писателем. Черновик автоматически сохраняется в библиотеку активов как `Chapter_X_Draft.md`.
4. **CRITIQUE (Литературный контроль):**
   * Критик формирует вердикт («Что удалось», «Что требует исправления», «Оценка стиля и логики (1-10)»).
   * Пользователю доступны две главные команды:
     * **«Принять правки»:** Запускает цикл доработки — Писатель переписывает главу, а Критик проводит повторный аудит (Re-review).
     * **«Утвердить и дальше»:** Глава утверждается, сохраняется версия `Chapter_X_Final.md`, и Писатель приступает к следующей главе.
     * **«Завершить книгу»:** Переход к этапу релиза.
5. **RELEASE (Релиз и публикация):**
   * **«Скомпилировать книгу»:** Программная сборка чистой рукописи `{BOOK_NAME}.md` без системных логов и критики.
   * **«Маркетинг и Обложка»:** Дизайнер формирует аннотацию, промо-посты и концепцию обложки.

## 4. Ключевые технологические решения

### 4.1. Умная фильтрация контекста (Smart Context Filter & Narrative Bridge)
Чтобы не перегружать контекстное окно Gemini и экономить токены:
* **Story Bible, Lore и Style** передаются всегда как неизменный базис истории.
* **Тексты завершенных глав исключаются из контекста**, вместо этого используется **Narrative Bridge (Нарративный мост)** — последние 5000 символов предшествующей главы, явно внедряемые в промпт для сохранения темпа и бесшовного повествования.

### 4.2. Система версионирования и отката (Chapter Rollback)
* При каждом утверждении создается снимок состояния `Chapter_X_Final.md` в категории «ВЫВОД».
* В Памяти проекта пользователь может открыть любую прошлую главу и нажать **«Откатиться к этой версии»**:
  * Система с подтверждением удалит последующие главы, восстановит выбранный текст и вернет проект на стадию `CRITIQUE` для этой главы.

### 4.3. Чистая компиляция рукописи (`CMD_COMPILE_MANUSCRIPT`)
* Сборка итогового файла происходит локально на клиенте без расхода токенов.
* Собираются только утвержденные финальные главы `Chapter_X_Final.md`, исключая черновики, рецензии критика и реплики редактора.
* Итоговый файл именуется по названию книги (например, `Хроники_Пустоты.md`) и помещается в категорию `output`.

### 4.4. Надежное сохранение состояния
* Все состояние приложения непрерывно синхронизируется с `localStorage` по ключу `VSF_APP_STATE_V2`.
* Доступен экспорт всего проекта в один `.json` файл и импорт проекта обратно.
* Функция безопасного сброса сессии («Начать заново») с кастомным диалогом подтверждения без использования `window.confirm` и `window.location.reload()`, что критично для работы внутри iframe.

## 5. Пользовательский интерфейс (UI / UX)

* **Верхняя панель (ProgressBar & Header):**
  * Индикатор текущего этапа (INIT → BRIEF → WRITING → CRITIQUE → RELEASE).
  * Индикатор активного агента с цветовой кодировкой и анимацией работы.
  * Real-time счетчик затраченных токенов (Input / Output / Total).
  * Кнопки управления: «Новый проект / Сброс», «Экспорт в JSON», «Загрузить JSON».
  * Переключатель режима: **Режим чата** ↔ **Режим книги (Reader View)**.
* **Центральная зона:**
  * **Режим Чат (ChatInterface):** Диалог с агентами, форматирование Markdown, вложение пользовательских файлов (текст, изображения, PDF), контекстные кнопки быстрого действия под полем ввода.
  * **Режим Книга (Reader View):** Двухколоночный интерфейс читалки с оглавлением, статусами глав (`draft`, `review`, `final`) и комфортным просмотром текста.
* **Правая панель (Asset Library — Память проекта):**
  * Вкладки по категориям:
    * 📎 **Референсы** (`reference`) — материалы, загруженные пользователем.
    * 🎨 **Стиль** (`style`) — гайды по стилю и тону.
    * 📜 **Лор** (`lore`) — Story Bible, описания мира и персонажей.
    * 📁 **Вывод** (`output`) — черновики, финальные главы `Chapter_X_Final.md` и скомпилированная книга.
  * Модальное окно просмотра файла с возможностью копирования, скачивания в `.md` и запуска процедуры отката (Rollback).

## 6. Структура проекта

```
├── App.tsx                     # Главный компонент, оркестратор стейта, логика этапов и команд
├── types.ts                    # TypeScript-интерфейсы (Role, Stage, Asset, Message, StoryContext)
├── metadata.json               # Метаданные приложения и имя версии (Virtual Story Factory_2.3)
├── package.json                # Зависимости (@google/genai, react, lucide-react, marked, vite)
├── index.html                  # HTML-шаблон с точкой монтирования и шрифтами
├── index.tsx                   # Точка входа React
├── vite.config.ts              # Конфигурация Vite
├── tsconfig.json               # Настройки компилятора TypeScript
│
├── services/
│   └── geminiService.ts        # Клиент GoogleGenAI, персоны агентов, Smart Context Filter, ре-ревью
│
└── components/
    ├── ProgressBar.tsx         # Верхняя статусная панель, трекинг агентов и токенов
    ├── ChatInterface.tsx       # Чат, быстрые действия, рендеринг ролей, загрузка вложений
    ├── ReaderView.tsx          # Полноэкранный режим чтения книги с боковым оглавлением
    ├── AssetLibrary.tsx        # Библиотека памяти проекта, категории, просмотр и откат
    └── MarkdownRenderer.tsx    # Безопасный рендерер Markdown с подсветкой и стилями
```

## 7. Стек технологий

* **Фреймворк:** React 19 + TypeScript
* **Сборщик:** Vite 6
* **Стилизация:** Tailwind CSS
* **Иконки:** Lucide React
* **Работа с Markdown:** Marked
* **Искусственный интеллект:** Google GenAI SDK (`@google/genai`), модели:
  * `gemini-3-pro-preview` — генерация высококачественного литературного текста.
  * `gemini-3-flash-preview` — логический анализ, аудит критика, Story Bible и маркетинг.

## 8. Запуск и разработка

### Переменные окружения
Для работы приложения необходим ключ Google Gemini API:
```env
API_KEY=your_gemini_api_key_here
```

### Команды
* Установка зависимостей:
  ```bash
  npm install
  ```
* Запуск в режиме разработки:
  ```bash
  npm run dev
  ```
* Сборка для продакшена:
  ```bash
  npm run build
  ```
* Локальный предпросмотр сборки:
  ```bash
  npm run preview
  ```
